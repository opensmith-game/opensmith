# Contributing to OpenSmith

Thanks for wanting to help. OpenSmith is a guitar game for macOS in three parts:

| Folder | What | Language |
|---|---|---|
| `engine-rt/` | real-time audio: pitch detection, note tracking, amp, CoreAudio, game rules | Rust |
| `app/` | the desktop app: Tauri v2 shell (`src-tauri`) and the note highway, HUD and screens (`src`, Three.js) | Rust + TypeScript |
| `pipeline-ingest/` | songs and tabs → playable charts: Demucs, Basic Pitch, Viterbi fingering, Guitar Pro / XML import, plugin commands | Python |
| `schema/` | the chart format shared by all three | JSON Schema |

The guitar signal never goes through Python or JavaScript: everything time-critical is Rust.

## Set up

You need an Apple Silicon Mac, [Rust](https://rustup.rs), Node 20+, [uv](https://docs.astral.sh/uv/) and ffmpeg:

```bash
brew install node uv ffmpeg
```

```bash
cd pipeline-ingest && uv sync
```

```bash
cd app && npm install
```

Run the desktop app from the repository (it uses this checkout's `pipeline-ingest` and `out/`):

```bash
cd app && npm run tauri dev
```

Or only the note highway in a browser, with an automatic player instead of a guitar:

```bash
cd app && npm run dev
```

## Tests

Every change comes with its tests, and CI runs all of these on each pull request:

```bash
cargo test --workspace
```

```bash
cd app/src-tauri && cargo test
```

```bash
cd app && npx tsc --noEmit -p . && npx vitest run
```

```bash
cd pipeline-ingest && uv run pytest
```

The end-to-end pipeline runs (stem separation and transcription on a synthetic song, about a
minute) are not in CI; run them when you touch the pipeline:

```bash
cd pipeline-ingest && uv run pytest -m slow
```

Tests are deterministic: DSP code is tested on generated signals (a 82.41 Hz sine must come out
as the low E string), the pipeline on generated songs with known notes. Tests needing real
audio devices are `#[ignore]`d and run by hand with `-- --ignored`.

## Conventions

- **Interface text** is written in French in the code and wrapped in `t()` / `tn()` from
  `app/src/i18n.ts`; add the English to the matching file of `app/src/locales/en/`. A test
  fails when a text has no English.
- **Comments** say why, in full sentences, at the density of the code around them.
- **Commits**: one change per commit, a short title in the imperative or a plain description,
  a body saying what changed for the player and why.
- `PROGRESS.md` (in French) logs what was built and measured: add to it for anything a player
  or contributor would notice.

## Plugins

Other import formats come as plugins of the song converter: a Python package with an entry
point in the `opensmith_ingest.commands` group. The entry point adds a command to
`opensmith-ingest` and returns the function that runs it; its `formats` attribute lists the
file extensions it imports (see `pipeline-ingest/src/opensmith_ingest/cli.py` and
`tests/test_plugins.py`). Installed into the converter's environment, the plugin's files are
accepted by the app.

## What never goes in the repository

- Music or recordings you don't have the rights to share. The demo song is generated by
  `opensmith-ingest demo`.
- Files taken from games, and decryption code or keys.
- Your library (`out/`), virtual environments, build output.

## Reporting bugs

Open an issue with the bug template: macOS version, Mac model, audio interface, and what you
did. For a song that converts badly, say where it came from (MP3, Guitar Pro, a plugin), but
don't attach copyrighted audio.
